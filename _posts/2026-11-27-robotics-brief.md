## 1. xFORM：不丢弃几何对应，把每对扫描压缩为 34 个标量残差

时间回补｜v1 2026-11-25 UTC。 [论文](https://arxiv.org/abs/2611.34053) · [方法及实验表格](https://arxiv.org/html/2611.34053v1)

### 为什么重要

多路雷达加密扫描后，真正昂贵的不只是地图大小，而是滑窗中成千上万匹配在每一次迭代都要重新计算残差、Jacobian 和线性系统。CMU 的 xFORM 在原有 FORM 固定滞后激光里程计基础上，利用点和面残差对相对位姿表达的特殊代数结构，压缩重复工作。

### 算法模块

```text
点/平面特征提取 → 扫描间建立对应
                      ↓
         按扫描对构造系数矩阵
                      ↓
          双精度 Householder QR
                      ↓
        34 维压缩残差 / 扫描对
                      ↓
          滑窗 LM 优化与边缘化
```

压缩前后的目标值及 Gauss–Newton 系统在对应固定、权重模型满足论文条件的精确算术中保持相同。构造摘要仍需遍历匹配；重新匹配后要更新摘要。优化器本身仍在 CPU 上运行，GPU 版将特征、对应搜索与摘要计算移至 GPU。

### 实验与实时性

15 条完整序列、三个数据集；下表为作者表 II 中每扫描平均耗时及 GPU P95（ms）。

| 数据集 | FORM 平均 | xFORM CPU 平均 | xFORM GPU 平均 | GPU P95 |
|---|---:|---:|---:|---:|
| Newer College | 112.20 | 90.75 | 30.85 | 51.47 |
| Hilti | 56.86 | 43.59 | 25.32 | 61.50 |
| MCD | 71.27 | 59.79 | 23.46 | 39.20 |

跨序列 CPU 平均约 1.2 倍、GPU 约 3 倍加速。相对原 FORM 的最大位置数值差约 1.2e-8 m，**这是两套实现的一致性，不是对真值的定位误差**。例如 MCD 的 30 m 分段 RTE 为 0.5478 m。计时不含输入加载、输出序列化及初始 20 帧。

### 假设、风险与工程落地

原方法使用固定对应和同一扫描对共同的各向同性权重；姿态相关鲁棒权重、异方差观测以及 IMU 联合状态需要重新推导，不能直接套用 34 维结论。它是 LO 而非完整多雷达 LIO，论文输入也未去畸变。

适合三雷达滑窗后端、Ceres/GTSAM、边缘 GPU。建议先离线实现单扫描对 QR 压缩，逐次对比 cost、JᵀJ、Jᵀr、优化增量和特征值；再把三雷达分开建立对应并联合优化同一机体状态。以相同匹配集比较 RSS、迭代 P95、RPE 和退化方向，不用减少观测作为加速的代价。完整 xFORM 源码未独立核实。

## 2. 轮足机器人葡萄园探索：简单几何能跑 370 米，但稀疏结构下行间切换仍不可靠

时间回补｜v1 2026-11-25 UTC。 [论文](https://arxiv.org/abs/2611.34246) · [全文](https://arxiv.org/html/2611.34246v1)

### 为什么重要

重复排列的葡萄架和工业长走廊具有类似的感知难题：局部横向边界清晰，但纵向识别和通道切换困难。作者使用 Unitree Go2 Wheeled，把激光几何与有限状态机结合，不依赖大型语义模型。

### 算法模块与结果

激光点云 → 空间过滤 → 迭代 RANSAC 直线检测 → 行中心方向 → 有限状态机选择及穿越下一行。英国 Denbies Vineyard 实地实现约 370 m 往返自主行驶，无人工干预；但稀疏植被导致行线不稳定，跨行转移仍有失败模式。它不是无人工干预的整个葡萄园覆盖认证，也没有证明厘米级绝对定位。

### 工程启发

适合轮足机器人通道巡检和弱几何环境。可在已有定位之上加入左右边界时间一致性检测、短时间失测保持和重新观测状态；不能用边界拟合取代绝对位姿。用录制数据比较单帧 RANSAC、时间滤波及自适应过滤，记录误选通道、横向偏差、转移成功率及 CPU P95。楼梯入口仍需独立姿态准入。完整代码未核实。

## 3. 黑盒 Agent 测试选择：100 道题估计 Codex 总体表现，而不是每次跑满 500 道

时间回补｜v1 2026-11-25 UTC。 [论文](https://arxiv.org/abs/2611.34617) · [实验方法](https://arxiv.org/html/2611.34617v1)

### 为什么重要

改动 MCP、Skill 或模型配置后，完整 Agent Benchmark 很昂贵；随机抽样虽便宜，却可能遗漏重要任务类别。研究将传统黑盒回归测试选择迁移到 Agent 测评，不要求目标模型的内部参数。

### 方法与实验

按任务描述、代码和元数据划分任务类别，或使用任务难度估计选择样本。14 种选择策略在 10 个基准上对比。作者对 GPT-5.2 Codex 的 SWE-bench Verified 实验中，类别分区以 100/500 任务、47 美元对完整评测 225 美元，得到 0.8 个百分点的成功率估计误差。另一难度选择方案中，53.0% 入选任务失败，随机选择为 27.4%。后者有意寻找失败，不能把该样本的通过率直接当作总体通过率。

### 工程落地与风险

适合 Codex/T3 Code 工作流评测。将 50–100 个真实仓库任务按语言、模块、故障、工具和风险划分，每类固定代表任务；一组用于总体估计、一组用于早期暴露失败。保留独立完整测试集、随机种子、每类权重和置信区间，定期用全量集校准。选择模型可能引入额外 API 成本；确定性类别划分无需 API。论文完整运行工程未独立核实，本期未运行任何模型评测。

## 4. FOCI：高斯地图也能用来规划机器人朝向，而不只是渲染场景

时间回补｜v1 2026-11-24 UTC；2025 IROS 工作的期刊扩展，本期首次覆盖。 [新论文](https://arxiv.org/abs/2611.33380) · [IROS 原版](https://arxiv.org/abs/2505.08510) · [MIT 源码](https://github.com/leggedrobotics/foci)

### 为什么重要

矩形机器人、长机身无人机和机械臂在窄空间的可通行性与朝向有关。用一个很大的包围球容易过度保守。FOCI 将机器人本体也表示成高斯，利用高斯之间重叠积分作为可微碰撞代价，联合优化位置与姿态。期刊版本覆盖静态及动态高斯场景、足式/机械臂/无人机。

### 算法模块

机器人高斯随关节和姿态变换 → 环境高斯查询 → 重叠积分与梯度 → 轨迹优化（可加入运动约束）→ 连续轨迹复查。

### 实验与边界

作者表 V 中，Bonsai 约 56.9 万环境高斯、机械臂 6 个本体高斯，求解 3.059 s，对照 CHOMP 为 29.276 s；Coffee Table 约 66.8 万环境高斯，FOCI 0.528 s、CHOMP 48.291 s。Forest 无人机约 240 万环境高斯时 FOCI 0.532 s，CHOMP 0.011 s（较快但其轨迹在该场景擦碰，不能只看时间）。初始路径生成时间单独计算，秒级求解不是毫秒级控制周期。

高斯密度不等同于真实占据概率；未重建障碍、薄结构、动态地图误差都可能导致错误。真机仍需独立激光安全地图及停车保护。

### 开源与最小复现

已独立读取 README 和 MIT LICENSE。安装要求另行取得 [Coin-HSL MA27 求解器许可](https://licences.stfc.ac.uk/product/coin-hsl)；第三方 Polycam 场景是独立 CC BY 4.0 资产。

```bash
git clone https://github.com/leggedrobotics/foci.git
cd foci
# 按官方说明将有合法许可的求解器解压至 coinhsl/
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# 按 README 下载 PLY 到 data/
ls demos
# python3 -m demos.<实际示例模块名>
```

未实际安装。适合多摄像头三维地图、狭窄空间机器人和数字孪生。用同一真实几何比较膨胀体素图与方向感知高斯规划的可行率、净空和求解 P95，再决定是否需要将它纳入候选规划层。不要直接取代安全占据图。

## 5. RGB-D 模仿学习：深度空洞比测距噪声更容易摧毁策略收益

时间回补｜v1 2026-11-24 UTC。 [论文](https://arxiv.org/abs/2611.33352) · [完整实验](https://arxiv.org/html/2611.33352v1)

### 为什么重要

双目相机在反光、遮挡和无纹理区域会出现深度空洞。以往讨论常集中在毫米级测量噪声，却忽略了有效像素比例。作者以真实腕部双目相机标定的传感器模型，在仿真中对 ACT 和三类视觉编码器分别注入噪声与缺失。

### 实验与工程边界

完整深度相对 RGB 的成功率改善约 10 个百分点；将噪声增至相机标定噪声的 20 倍仍保留多数收益；约六分之一腕部图像出现深度空洞就可能消除可检测的收益。有效性掩码影响策略是否依赖深度，训练时完整而部署时有空洞也会导致退化。以上是指定仿真及训练协议，不是所有 D455 或 VLA 的实测结论。

### 可复现性与工程启发

完整官方实现未核实。适合 RGB-D、BEV、视觉操作。最小实验：固定真实视频或仿真序列，分别加入随机距离噪声、空间相关空洞和错误填补；比较原始无效掩码与有标记填充，记录覆盖率、深度误差、下游任务成功率。填补像素只能用作估计，不应当作真实碰撞证据。对于多相机重建，应优先保留深度有效性与来源信息。

## 6. RoboARC：Codex 在全知仿真状态下成功 86%，仅靠传感器降至 43%

时间回补｜v1 2026-11-24 UTC。 [论文](https://arxiv.org/abs/2611.33390) · [项目](https://roboarc.embodied-first-exam.ai/) · [MIT 仓库](https://github.com/mll-lab-nu/RoboARC)

### 为什么重要

许多机器人操作难点不是语言理解，而是精确形状、间隙、接触与运动约束。RoboARC 设计 90 个固定物理场景、6 类约束、3 种机器人配置，以可回放参考轨迹和独立物理评分器进行测试。

### 结果

| 评测设置 | 结果 |
|---|---|
| Codex / GPT-6 Astra，完整仿真状态及可重置 | 86% |
| 同一 Agent，传感器与本体状态、单次尝试 | 43% |
| 四个零样本 VLA，在指定 18 个单臂题 | 均未解出 |

作者对 15 个有代表性的困难案例注入物体位姿与零件几何，联合提供两者使指定子集成功率由 24% 提至 60%。这不能解释为所有真实机器人任务都有相同提升；两种评测模式还存在可重置性差异。

### 开源与最低复现

已核实 README：Linux x86_64、Python 3.11+、NVIDIA RT GPU（驱动 580+）、Docker 与 NVIDIA Container Toolkit。镜像约 19 GB，第三方许可独立；匿名镜像拉取在本轮未验证。

```bash
git clone https://github.com/mll-lab-nu/RoboARC.git
cd RoboARC
uv venv --python 3.12
source .venv/bin/activate
uv pip install -e .
roboarc --version
roboarc list
roboarc selftest --print
```

官方建议安装 Harbor 0.27.0，审查并接受第三方许可证后拉取固定摘要镜像，再运行 `roboarc selftest interlocked-claws-08` 验证 oracle / nop 两组，无需模型。完整 Codex 实验需独立 API 凭据与授权，本次未执行。

### 适合谁关注与工程落地

适合 VLA、操作规划和具身 Agent。对于仅开放厂商 SDK 的机器人，优先把可信物体位姿、场景碰撞几何、可执行技能接口暴露给高层，而不是让模型直接控制电机。记录观测错误、规划失败和执行失败三类指标，不要只测总体成功率。

## 7. 无人机吊载 MPC：学习热启动并不总能击败传统移位热启动

时间回补｜v1 2026-11-24 UTC。 [论文](https://arxiv.org/abs/2611.33514) · [全文](https://arxiv.org/html/2611.33514v1)

### 为什么重要

MPC 每个周期求解相似优化问题，Transformer 可以预测初始控制序列，但经典方法直接移动上一次求解序列也很有效。该研究使用弹性吊索与双摆模型，比较零初始化、移位初始化和 Transformer 初始化，之后均用同一 SCP 优化器修正。

### 实验与限制

独立优化问题中 Transformer 比零初始化耗时少；连续闭环仿真中，移位热启动反而最省时间，三种方法跟踪表现类似。论文明确承认优化耗时超过控制采样周期，**没有证明实时部署**。完整源码未核实。

### 工程启发

适合无人机、轮式底盘 MPC 和轨迹优化。最低实验先固定模型、约束、预测时域、求解容差与硬件，比较零初始化、上次轨迹移位、学习初始化。尤其要注入目标突变、外部扰动及不可行初值，记录 P95、P99、约束超限、可行解率和跟踪误差。学习模型的前向延迟必须计入总时延。不能仅因为预测初值比零初值好，就认定有实际价值。

## 8. GhostAPI-V：API 迁移既要检查新接口被正确使用，也要检查旧接口彻底退出

时间回补｜v1 2026-11-24 UTC。 [论文](https://arxiv.org/abs/2611.33396)

### 为什么重要

Coding Agent 修改 SDK 接口时，容易只增加新函数而保留旧调用路径，测试通过也可能遗漏运行期分支。作者把版本迁移要求写成经人工审计的双向契约，提供针对候选补丁的诊断，再用独立隐藏行为测试验收。

### 实验结果

8 个 Python 仓库、48 个内部 API 迁移，两个 Agent，每任务每 Agent 两次初始运行，共 192 个候选。原始版本差异反馈通过 120/192（62.5%）；仅必需契约 130/192（67.7%）；完整契约 148/192（77.1%）。差值 14.6 个百分点是混合 Agent 总体结果，不是 Codex 单独增益。禁用旧行为的独立贡献对分析口径敏感；符号检查和行为测试也可能不一致。

### 工程落地

适合 C++/ROS SDK、SIP 接口迁移及大型工程。写三种断言：必须出现的新行为、禁止存在的旧行为、应保持的历史兼容行为。先用确定性静态检查定位候选违规，再跑独立行为测试；不允许靠删功能来通过检查。源码与完整复现包尚未核实。建议以真实迁移任务评估首次通过率、遗漏旧分支、误报及修改范围。

## AI / LLM 附属框架与开源工程组件

### SkillsBench Lift Reanalysis：本地审计 Skill 效果到底来自能力提升，还是评分器偏差

时间回补｜v1 2026-11-25 UTC。 [论文](https://arxiv.org/abs/2611.33943) · [审计代码](https://github.com/rrrrr4788/skillsbench-lift-reanalysis)

**痛点与关键模块：** 有无 Skill 对照并不一定公平，评分器可能只认可 Skill 中声明的额外要求，或执行环境偷偷加载其他 Skill。该项目提供标准化试验表、源码审计账本、统计检验、门控策略复算及可复现脚本。它是评测辅助组件，不是在线 MCP 服务、LLM 或可自动优化所有 Skill 的工具。

作者重新分析 7,554 次公开试验、1,421 个配对单元；发现 3 项任务的评分/定义存在受控验证的问题（其中两项为评分依赖），这三项平均提升 74.6 个百分点，整个样本平均 18.7 个百分点。四项任务使用占位 Skill 目录，某执行器另注入 48 项内置 Skill。多重检验校正后未找到显著的单任务负向收益。每组至多三次试验，不能凭一次失败就判定某 Skill 有害；也不能据此断言所有 Skill 都有效。

**开源与最小运行：** 已核实 README、MIT LICENSE。Python 3.10+；针对仓库已有归一化数据的统计复算无 GPU、无模型 API。原始轨迹、上游任务文件及部分泄漏审计数据为外部依赖。

```bash
git clone https://github.com/rrrrr4788/skillsbench-lift-reanalysis.git
cd skillsbench-lift-reanalysis
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -B reanalysis/check_inputs.py .
python -B reanalysis/skillgate_checks.py . outputs/reproduction base
python -B reanalysis/skillgate_checks.py . outputs/reproduction exact
```

完整复算还需要 README 所列 tasks、seeds、null、split 子命令；本轮仅核实入口，未运行。上游材料遵守各自许可证。

## AI Coding 实战技巧精选

### 技巧 1｜用 git interpret-trailers 给 Codex 提交附上可解析的测试证据索引

- **来源：** Git 项目维护者，[官方手册](https://git-scm.com/docs/git-interpret-trailers)，工程补充回顾（非当日新版本）。
- **一句话结论：** 不要把测试证据全部埋进自由文本，使用结构化提交尾注供独立审查读取。
- **具体怎么做：** 实际运行测试，保留日志或 CI 产物链接；在准备提交时生成消息文件并追加尾注；审查端提取尾注与真实产物比对。

```bash
printf 'fix: repair localization reset\n' > /tmp/commit-msg.txt
git interpret-trailers --in-place \
  --trailer 'Test-Evidence: local-ctest-log' /tmp/commit-msg.txt
git interpret-trailers --parse /tmp/commit-msg.txt
# 核对真实测试产物后才使用 git commit -F /tmp/commit-msg.txt
```

- **适合什么场景：** Codex、T3 Code 多任务交付、C++/ROS2 和轻量 CI。
- **注意：** 尾注只是声明，不是签名或成功证明，CI 应独立核对产物；不要把秘密或本地敏感路径放入提交。

### 技巧 2｜用 git show-ref --verify 确认 Agent 操作的是精确分支

- **来源：** Git 项目维护者，[官方手册](https://git-scm.com/docs/git-show-ref)，工程补充回顾。
- **一句话结论：** 多工作树自动化传入分支名时，先检查完整 ref 与预期 SHA，避免同名标签、远程分支或错误目标。
- **具体怎么做：**

```bash
git show-ref --verify refs/heads/feature/localization
git show-ref --verify --quiet refs/heads/feature/localization
git rev-parse --verify HEAD
git worktree list --porcelain
```

- **适合什么场景：** T3 Code 并行任务、Git 归档脚本、Codex 集成检查。
- **注意：** 本地 ref 存在并不保证远端仍是相同 SHA；写远端前另做最新 ref 核验，不用强制推送规避冲突。

## 经典论文回顾

### Square Root SAM：从稀疏图结构到测量残差的代数压缩

经典复盘（首次覆盖 2026-09-13，本次不增加唯一条目）。Frank Dellaert、Michael Kaess，IJRR 2006 年 12 月，25(12):1181–1203。[原论文 DOI](https://doi.org/10.1177/0278364906072768) · [RSS 2020 Test of Time](https://roboticsconference.org/2020/program/testoftimeaward/index.html) · [现代 GTSAM](https://github.com/borglab/gtsam)。

### 数学思想与历史价值

线性化后的最小二乘可写成 min ||Aδ-b||²。若 A=QR，正交变换保留二范数，将问题转换为上三角系统 Rδ=Qᵀb（并保留与 δ 无关的残差项）。原工作利用稀疏结构和变量排序降低填充，将平滑与图模型联系起来，避免 EKF 全量稠密协方差更新。后来 iSAM/iSAM2 进一步处理增量更新与选择性重线性化。

### 本次新的复盘角度

Square Root SAM 主要解决变量消元的稀疏性，而今天的 xFORM 在消元前就利用扫描对残差的结构降低行数：前者控制 R 的填充，后者减少反复生成 Jacobian 的代价。两者互补，不等同于直接把 QR 当作地图下采样。

### 假设与可复现性

需要正确线性化、测量关联、权重以及固定坐标系的 gauge；QR 不会创造退化方向的信息。xFORM 的等价性也并非自动适用任意鲁棒核。可用 Eigen HouseholderQR 对同一白化矩阵做小规模实验，对比直接最小二乘、正规方程和 QR，再用 GTSAM 比较变量排序与因子图求解。历史代码未独立核实，现代 GTSAM 是参考实现而非原版。适合多雷达后端：分别统计原始匹配数、压缩后残差数、变量数、消元填充、重线性化成本与最终 RPE。

## 今日结论

第一，三雷达融合的优化重点可以从丢弃点转到压缩重复计算。xFORM 的固定维度因子摘要值得独立实现，前提是保留原有统计权重并严格验证数值等价。第二，FOCI 与 RoboARC 共同说明真实几何对运动规划和具身推理有很高价值，但视觉重建不能单独承担安全职责。第三，Codex 评测应先确定评分器独立性和任务代表性，再讨论 Skill 带来的收益；不要在没有授权的情况下启动大规模模型评测。
